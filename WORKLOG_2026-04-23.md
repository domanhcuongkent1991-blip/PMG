## Update 2026-04-23 (PA-04: local-first sync safety)
- Goal:
  - Improve offline-first safety and reduce risk of data loss during concurrent edit + sync.
- Key risks addressed:
  - stale overwrite when sync success marks old snapshot as `SYNCED`
  - remote refresh overwriting local `PENDING` edits
  - queue cleanup removing entries created during an ongoing sync
- Changes:
  - `syncPending()` hardening in repository:
    - use a queue snapshot (`queueSnapshot`) per sync run
    - build candidate logs by distinct `recordId` from snapshot
    - on success, mark local row `SYNCED` only when current `updatedAt` exactly matches pushed snapshot
    - delete only snapshot queue rows by `id` (new rows created during sync are preserved)
  - `refreshFromRemote()` merge safety:
    - apply remote row only when local row is absent, or local is already `SYNCED` and remote is newer/equal by `updatedAt`
    - never overwrite local `PENDING` edits
  - added sync rule helpers:
    - `shouldMarkAsSynced`
    - `shouldApplyRemoteLog`
  - files:
    - `android-mvp/app/src/main/java/com/example/devicetracker/data/repository/DeviceLogRepositoryImpl.kt`
- Tests:
  - new:
    - `android-mvp/app/src/test/java/com/example/devicetracker/data/repository/DeviceLogRepositorySyncRulesTest.kt`
  - coverage:
    - mark-as-synced only when `updatedAt` matches
    - keep local pending edits against remote refresh
    - remote apply only for new record or newer/equal remote when local is synced
